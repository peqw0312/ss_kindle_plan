# 第 1 步 · 越狱与基础环境

> **本文针对 Kindle Paperwhite 3（第七代，2015 年，序列号前缀 G090G1，4GB）。**
> 其他型号的适配范围完全不一样，不要照搬。
>
> 越狱生态变化很快，**具体文件名和版本号请以社区官方文档为准**：
> - 英文（最权威）：<https://kindlemodding.org/jailbreaking/>
> - 中文（可参考）：<https://bookfere.com/post/326.html>
>
> 本文的作用是让你**知道整个流程长什么样、哪些地方会踩坑、为什么顺序不能错**，
> 而不是替代官方指引。请两边对着看。

---

## 0. 先确认固件版本，这一步不能跳

Kindle 上：**设置 → 设备选项 → 设备信息**，找到「固件版本」。

| 你的固件 | 能不能越狱 | 用哪个方法 |
|---|---|---|
| **≤ 5.16.2.1.1** | ✅ 可以 | **LanguageBreak**（语言包漏洞），本文走这条 |
| 5.16.2.1.1 以上 | ❌ 目前不行 | 不要硬来，会变砖。只能等社区出新方法 |
| 已经在 5.16.2.1.1 以上但想降级 | ⚠️ 有风险 | 需要先越狱才能降级，是个死循环 —— 这种情况去 MobileRead 论坛问 |

**如果版本高于 5.16.2.1.1，现在停手。** 后面的步骤一步都别做。

## 1. 风险知情与准备工作

### 风险有多大

诚实地说：**LanguageBreak 这条路成功率很高，但不是零风险**。

- 会**清空设备里的所有内容**（书、笔记、插件都会没），所以必须备份
- 中途断电或强行重启有可能导致系统损坏，需要重新刷固件救援
- 越狱会失去亚马逊的保修（不过 2015 年的机器早就过保了）

### 开工前的检查清单

- [ ] 电量 **50% 以上**（最好全程插着充电器，别用电池跑）
- [ ] 已经备份了 `documents` 文件夹（见下一节）
- [ ] 设备**没有设置锁屏密码**，有的话先取消
- [ ] 设备**根目录没有残留的固件升级文件**（`.bin`、`update.bin.tmp.partial` 之类），有就删掉
- [ ] 一根**靠谱的 USB 数据线**（劣质线是「电脑认不到 Kindle」的头号原因）
- [ ] 全程开**飞行模式**，不要连 WiFi

### 备份

用 USB 连电脑，把 Kindle 里整个 `documents` 文件夹复制到电脑上。
Kindle 会显示成一个 3.27 GB 左右的 U 盘，直接拖出来就行。

## 2. 越狱（LanguageBreak）

整个流程分三大段：**进演示模式 → 运行越狱 → 装热修复**。

### 2.1 重置设备并进入演示模式

1. 先做一次**恢复出厂设置**：设置 → 设备选项 → 重置
   （越狱会清空内容，不如主动重置，环境更干净）
2. 走完初始设置，**跳过 WiFi**，全程飞行模式
3. 在搜索框里手动输入（必须是英文半角分号）：

   ```
   ;enter_demo
   ```

   > ⚠️ 输入完不会有任何反应，**需要手动重启**才生效。别以为失败就重试。
   > 每一步命令都要**手动重新输入**，不要点搜索历史里的记录。

4. 重启后按提示走：跳过 WiFi → 注册信息随便填 → Skip → Standard → Done
5. 会白屏一会儿，然后进入**循环播放广告图的演示模式**

### 2.2 用秘密手势进入「图书馆」

演示模式默认会一直循环放图，必须用隐藏手势才能进去：

1. **两根手指同时轻点屏幕右下角**
2. 紧接着**一根手指从右向左横滑**
3. 多试几次，每次操作完等 1~2 秒

进去之后，搜索框输入 `;demo` 打开演示菜单。

### 2.3 导入越狱文件并运行

在演示菜单里选「**导入内容 / Sideload Content**」，然后连电脑，
把下载好的 LanguageBreak 文件按官方指引复制进去。

> **最容易踩的坑：要复制两次。**
> 演示模式下的分区和普通模式不一样，第一次复制完运行之后还需要再复制一次。
> 具体哪一步复制什么，**严格看 kindlemodding.org 的指引**，这里不能凭印象。

> **另一个坑：不要联网点商店。**
> 这一步很多人失败，是因为联网时亚马逊会重新下载商店文件，把刚放进去的越狱文件覆盖掉。
> 如果官方指引里有涉及商店的操作，正确顺序是「**先离线点开，再联网**」。

屏幕开始滚代码 + 自动重启 = 越狱成功。

### 2.4 装 Hotfix 并**运行**它，这一步别省

**越狱成功 ≠ 安全**。还要装热修复，否则一次系统更新就可能把越狱弄坏。

1. 下载 hotfix 包（官方渠道，文件名形如 `Update_hotfix_universal.bin`
   或 `Update_jailbreak_hotfix_*.bin`）
2. 拷到 Kindle **根目录**（根目录里**不能有别的 `.bin` 或
   `update.bin.tmp.partial` 之类残留**，有就删掉，否则这次更新会被忽略）
3. Kindle 上：**设置 → 右上角三点菜单 → 更新您的 Kindle**，问就选「更新」
4. 装完之后，**书库里会出现一个小册子 `Run Hotfix`，必须点开跑一遍**
   —— 只拷文件不运行等于没装。官方文档把这两步分得很开，第 4 步最容易漏
5. 等它跑完重启

> **⚠️ hotfix 版本必须 ≤ 2.3.7，不要用最新的 2.5.x。**
> 原因：hotfix 2.5.0 换了 KUAL 的签名证书，结果是 **KUAL 图标会正常出现在书库里、
> 但一点就报** `Application Error / The selected application could not be started`。
> 有 PW3 用户实测踩过这个坑，而且**降级回 2.3.7 也修不好，只能重新越狱**。
> 2.3.7 下载地址：<https://github.com/KindleModding/Hotfix/releases/tag/v2.3.7>

> **判断越狱活着的最快办法**：搜索框里输入 `;log`（就一个分号加三个字母），
> 有输出就是活的。**完全没反应不代表越狱失败** —— 先回头确认 hotfix 装了没、跑过了没。

下面这个土办法更直白。在 Kindle 根目录建一个 `RUNME.sh`，内容：

```sh
#!/bin/sh
eips 0 0 'Hello World!'
```

搜索框输入 `;log runme`。屏幕左上角出现 `Hello World!` 就说明越狱活着。

## 3. 装 KUAL 和 MRPI

KUAL 是后面的操作面板，没它就没法点菜单启动信息屏。

**这一步没有任何"安装动作"，全是"往哪拷"** —— 文件放对位置就装好了，
不需要输命令、也不需要重启。所以唯一的失败原因就是放错了位置。

> **先确认 hotfix 已经装好并且运行过**（见 2.4）。`;log` / `;log mrpi` 这些命令
> 是靠 hotfix 提供的，hotfix 没跑，后面所有 `;log` 都不会有任何反应。

### 3.1 下什么

| 东西 | 下哪个版本 | 地址 |
|---|---|---|
| **KUAL** | **PEKI** —— K5 及更新机型用这个，PW3（第 7 代）属于 K5 | <https://github.com/KindleTweaks/PEKI/releases/latest/download/PEKI.zip> |
| **MRPI** | **modern devices** 版 | <https://kindlemodding.org/jailbreaking/Legacy/post-jailbreak/kual-mrinstaller-khf.zip> |

> PEKI 从 `releases/latest` 拿就行，**别去 tag 列表里挑 v1.1**（那是坏的）。
> PEKI 官方支持范围是 **5.12.2.2 及以上**，PW3 在范围内。
>
> MRPI 严格说本项目**用不到** —— 我们的 `aistatus` 是纯 KUAL 扩展，不走 `.bin` 包。
> 但它负责处理 `.bin` 包，以后装 USBNetwork、更新 hotfix 都要靠它，一起装掉省事。

### 3.2 拷到哪里

| 拷什么 | 拷到哪 |
|---|---|
| MRPI 解压出来的 **`extensions` 和 `mrpackages` 这两个文件夹** | Kindle **根目录** |
| PEKI 解压出来的 **`KUAL.sh` 和 `KUAL.jar`** | Kindle 的 **`documents` 文件夹** |

两个细节：

- MRPI 包里带的是 `extensions/` **文件夹本身**，要**合并**进根目录已有的
  `extensions/`，不是替换掉整个目录。后面我们还要往 `extensions/` 里放 `aistatus`。
- 下载下来的文件名里**不能有括号**。浏览器给重名文件加 `(1)` 后缀是常事，
  这种名字会让安装静默失败，拷之前先改掉。

### 3.3 验证

1. 电脑上**安全弹出** Kindle 再拔线（直接拔有可能只写了一半）
2. Kindle **书库**里会出现 **KUAL** 这一项，点开就是菜单
3. **怎么确认 MRPI 也进去了**：搜索框输入 `;log mrpi`，它应该有反应
   （打印日志，或提示没有包可装）。毫无反应就是文件夹没放对
4. 点了没反应 / 装不上：
   - 先看 Kindle 剩余空间是否 **≥ 220 MB**（不够会装不上；腾空间之前**先开飞行模式**，
     否则腾出来的空间会被它拿去下载 OTA 更新）
   - 再重启一次 Kindle 重试

## 4. 锁死自动升级（关键，别跳过）

越狱成功后**亚马逊的 OTA 更新并没有自动关闭**。如果不管，某天夜里它会静默升级，
你的越狱和所有插件一起失效。

### 4.1 先装 renameotabin 扩展

KUAL 自带菜单里没有这一项，要另外装一个扩展：

1. 打开 <https://kindlemodding.org/jailbreaking/prevent-auto-update/> 下载 `renameotabin`
2. 解压后，把里面的 **`extensions/renameotabin/`** 放进 Kindle 的 `extensions/` 里
3. 弹出、拔线

### 4.2 执行 Rename

KUAL → **Rename OTA Binaries** → 选 **Rename**。

原理是把系统里负责下载固件的可执行文件改名，让 OTA 流程直接失效。
不同版本可能叫 "Block OTA" / "Prevent OTA Update"，意思一样。

**做完之后，联网前再检查一遍**：`/etc/` 下那几个 OTA 相关的二进制应该已经变成
`*.bin.old` 之类的名字。

> **⚠️ 有一条硬规矩要反过来记：恢复出厂设置、刷官方固件、降级之前，
> 一定要先回 KUAL 点 `Restore` 把名字改回去。**
> 有用户就是没改回去就恢复出厂，结果卡在"开机强制检查更新"那一步进不去系统。
> **真卡住了还有救**（记下来以防万一）：把 `renameotabin.zip` 里的 `restore.sh`
> 拷到 Kindle 根目录、改名成 `emergency.sh`，然后重启。

> 另一个土办法：把 Kindle 存储塞到只剩 50~90 MB。空间不够，固件包根本下载不下来，
> 相当于天然的防升级结界。不过这是权宜之计，**正式做法还是 Rename OTA Binaries**。
> **顺序别搞反**：先把 KUAL / MRPI 装好（那时需要 220 MB 余量），再来塞满存储；
> 而且腾空间之前先开飞行模式。

## 5. 验证清单

动手配置信息屏之前，确认下面几条都成立：

- [ ] **KUAL 能从书库正常打开** —— 报 `Application Error` 就是 hotfix 版本太新，见 2.4
- [ ] `;log runme` 能打出 `Hello World!`（`;log` 本身有输出也算）
- [ ] `;log mrpi` 有反应（说明 MRPI 的两个文件夹放对了）
- [ ] KUAL 菜单里能看到 **Rename OTA Binaries** 这一项
- [ ] OTA 屏蔽已执行（点过 Rename），联网后固件版本不会自己往上跳
- [ ] 设备能正常连上家里的 WiFi

## 6.（可选）装 USBNetwork，开 SSH

**不装也能完成本项目** —— 所有文件都能通过 USB 拖拽完成，`refresh.sh` 也能从 KUAL 点。

但装了 SSH 之后排障会方便很多（能实时看日志、直接命令行测试）。

1. 装 **USBNetwork** 插件
2. 在搜索框输入 `;debugOn`，然后 `~usbNetwork`，再 `;debugOff`
3. USB 连电脑，`ssh root@192.168.15.244`，默认密码通常是 `mario`
4. 连上后先执行 `mntroot rw` 把文件系统改成可写（**改完记得 `mntroot ro` 改回去**）

> **SSH 公钥的坑**：Kindle 的 SSH 服务只认 `ssh-rsa` 格式的公钥，
> `ssh-ed25519` 会莫名其妙连不上。别在这上面浪费时间。
> 另外 Kindle 上的 Dropbear 通常必须**关掉屏幕保护/密码**才能连。
