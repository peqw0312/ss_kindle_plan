## 一、为什么这次改动很小（先说结论）

现在的架构（2026-09-29 起）跟云端自建那条路**结构上是一样的**，只是跑在你电脑上：

```
dashboard/serve.py  =  抓数据 + 排版 + 发图 + 托管调试台   ← 单进程、单端口
Kindle              =  curl http://IP:8731/dashboard.png
```

也就是说**不用恢复任何被删掉的文件**（`app.py` 早没了，也用不上）。
搬一台 Linux 服务器上，它就是那个 24 小时在线的出图端。

代码侧已确认（我逐个读过）：

| 项 | 结论 |
|---|---|
| 依赖 | 只有 `Pillow` / `PyYAML` / `requests`，`requirements.txt` 三行 |
| Windows 专有 API | **没有**。`serve.py` 纯标准库，`generate.py` 无平台分支 |
| 字体 | `fonts.book_for()` 找不到配置里那些 `C:\Windows\Fonts\...` 会**静默退回** Linux 的 Noto CJK，不报错 |
| 输出 | 固定 1072×1448 八位灰度 PNG，与平台无关 |
| 端口 | `--bind 0.0.0.0 --port 8731` 现成，改成公网监听零代码 |
| 定时出图 | `auto_build_loop()` 自带线程，每 `AUTO_BUILD_MINUTES`（默认 60）分钟一轮 |

## 三、服务器规格（够不够）

按方案算过的实测数字：一次出图 **3 个网络请求 + 0.03s 排版 + 59KB PNG**，
一天最多 24 次（`AUTO_BUILD_MINUTES=60`）。

| 资源 | 需求 | 2核2G 够吗 |
|---|---|---|
| CPU | 一天 24 × 0.03s ≈ 1 秒 | 绰绰有余 |
| 内存 | 位图 1.55MB + Python/Pillow 常驻，按几十 MB 估 | 绰绰有余 |
| 磁盘 | 仓库 + Python 环境，约 1GB | 40GB 够 |
| **流量** | **见下** | ⚠️ 唯一要算的 |

### ⚠️ 流量是这次唯一要盯的数

Kindle 现在配的是 `FETCH_EVERY_MINUTES=1`（每分钟取一次），按 61KB/张：

```
24 小时 × 60 次 × 61 KB ≈ 88 MB/天 ≈ 2.6 GB/月
```

- 免费试用给的 **200GB/月**：完全够
- 学生套餐 **300GB / 500GB 月流量**：完全够
- 秒杀套餐 **300GB/月**：完全够

所以**流量不是问题**，但有个隐含代价要知道：**每分钟一次 = 服务器出口带宽被占用 1440 次/天**，
而且大陆节点 3–4M 带宽下峰值很平淡（61KB 一次），没有风险。
真嫌烦可以把 `FETCH_EVERY_MINUTES` 调到 10（月流量降到 260MB），代价是屏上内容最多旧 10 分钟。

## 四、执行步骤（预演，等你点头才动）

> 一键脚本已经写好在 **`guide/deploy-to-lighthouse.sh`**。
> 它做了五件事：装依赖 → **校验中文字体没退回 DejaVu** → 建 venv → 装包 →
> 生成 systemd 服务。凭据和代码上传它不碰，那两步要你/我来。
>
> 代码侧已确认 `fonts.py` 的候选路径里**已经包含 Ubuntu 的 Noto CJK 路径**
> （`/usr/share/fonts/opentype/noto/NotoSansCJK-Regular.ttc`），并且有 `.ttc`
> 的简繁字形选择逻辑 —— 这一条很关键，`.ttc` 用 index=0 可能拿到**日文字形**
> （「直」「骨」这类字写法不同）。装 `fonts-noto-cjk` 正好对上。

### 步骤 0 · 你在控制台做两件事（我做不了）

1. 登录腾讯云 → **轻量应用服务器** → 领**免费试用**（个人 2核2G / 1 个月）
2. 地域选 **上海**，镜像选 **Ubuntu Server 24.04 LTS 64bit**，记下**公网 IP** 和 **root 密码**

> 或者你把账号给我授权，我用 MCP 帮你建 —— 但**创建实例会花钱/占试用额度**，
> 而且需要你在控制台完成身份验证，建议你自己点，我负责后面的部署。

### 步骤 1 · 服务器基础环境（远程命令执行）

```bash
apt update && apt install -y python3 python3-venv python3-pip git
apt install -y fonts-noto-cjk          # 中文字体，不装屏幕上是方块 □□□
```

**字体是这一步的关键**。`config.yaml` 里写的是 `C:\Windows\Fonts\Noto Sans SC...`，
在 Linux 上不存在，`book_for()` 会退回扫描 fontconfig —— **必须确认它扫到的是
`Noto Sans CJK SC` 而不是 DejaVu**。装完我用 `fc-list | grep -i "cjk"` 验证。

### 步骤 2 · 放代码

两个选择，你定：

- **A. 打包上传**（推荐）：把 `dashboard/` + `kindle/extensions/aistatus/config.sh` 打成一个
  tar.gz，用 MCP 的远程命令把 base64 塞过去解包。不依赖你本地 git 环境（你这台机器
  的 git 推到 GitHub 那套已知有坑）。
- **B. 从你的 git 仓库 clone**：如果这个仓库有远端的话。需要你确认远端地址和可见性。

### 步骤 3 · 装依赖

```bash
cd /opt/kindle-plan
python3 -m venv .venv
.venv/bin/pip install -r dashboard/requirements.txt
```

### 步骤 4 · 传和风凭据（**不进仓库**）

现在凭据在 `.workbuddy/_qweather_local.env`（本机，被 gitignore 挡着）。
服务器上改成 **systemd EnvironmentFile**：

```ini
# /etc/kindle-screen/qweather.env   ← chmod 600，root only
QWEATHER_HOST=xxxxxx.re.qweatherapi.com
QWEATHER_ISS=...
QWEATHER_SUB=...
QWEATHER_KID=...
QWEATHER_PRIVATE_KEY_FILE=/etc/kindle-screen/qweather_ed25519.pem
```

> ⚠️ 私钥文件单独放，`chmod 600`。
> ⚠️ 我不会把私钥内容打进任何日志或对话里。
> `serve.py` 的 `load_local_env()` 读的是**仓库内相对路径** `.workbuddy/_qweather_local.env`，
> 服务器上要么留着这个文件（`chmod 600`），要么我给 `serve.py` 加一个
> `--env-file` 参数指到 `/etc/`。**我倾向前者：零代码改动。**

### 步骤 5 · 装 systemd 服务（开机自启 + 崩溃自愈）

```ini
# /etc/systemd/system/kindle-screen.service
[Unit]
Description=Kindle AI Screen (serve.py)
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/kindle-plan
EnvironmentFile=/etc/kindle-screen/qweather.env
ExecStart=/opt/kindle-plan/.venv/bin/python dashboard/serve.py --bind 0.0.0.0 --port 8731
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

这解决了现在最大的痛点：**你家那台 `serve.py` 不是开机自启的，崩了也没人知道**。

### 步骤 6 · 开防火墙端口

轻量服务器有**两层**防火墙：

1. **腾讯云防火墙**（控制台/MCP 管）→ 要放行 `TCP 8731`
2. **服务器本机 ufw/iptables** → 腾讯云轻量默认不开 ufw，通常只需第 1 层

> ⚠️ 放行 8731 意味着**公网任何人都能取到你的图**，图里有你所在城市（只精确到 2 位小数
> ≈ 1 公里）和自选行情。这和之前公益托管是同一级别的暴露。
> 介意的话有两个更稳的做法：
> - **只放行你自己的出口 IP**（你家宽带的公网 IP），但家宽 IP 会变，要维护
> - **加一个 URL token**：`/dashboard.png?k=<随机串>`，改 `serve.py` 加几行校验

### 步骤 7 · 验证

```bash
curl -I http://<公网IP>:8731/dashboard.png     # 应该是 200 + image/png + 有长度
```

以及重跑本机那套自检：

```bash
.venv/bin/python dashboard/tools/layout_check.py
```

### 步骤 8 · Kindle 端改地址（**只改一行**）

`kindle/extensions/aistatus/config.sh`：

```sh
# 云端为主，家里那台备用
DASHBOARD_URLS="http://<公网IP>:8731/dashboard.png http://192.168.31.158:8731/dashboard.png"
```

> ⚠️ 这里有个**顺序风险**：Kindle 是按顺序试、**第一个拿到合法 PNG 的就用它**。
> 现在家里那台排第一，如果云端排到前面，**回到家连 WiFi 时也走公网**（绕一圈），
> 而且云端挂了会自动退到家里那台 —— 这正是你要的"云端为主+家里备用"，逻辑是对的。
> 但要注意：**两台服务器出图内容可能不同版式**（因为各自读自己的 `skin.txt`），
> 状态不一致时调试台会显示"设备上贴的不是我这张"。README 里已记过这个坑。

然后拷进 Kindle（USB 整个目录重拷，或只改 config.sh 一个文件）。
