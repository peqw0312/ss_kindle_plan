## 三、怎么把文件传到服务器（**这套手法是踩了两轮坑才定下来的，别改**）

### 3.1 大文件：tar + lzma + base64 + **900 字符切块**

```
本机：tar czf - 文件 → lzma(preset=9|EXTREME) → base64
      ↓ 切成 900 字符/块的文本
每块：printf '%s' '<chunk>' >> /tmp/xxx.b64     ← 用 >> 追加，别用 >
      ↓ 每块执行完回报 wc -c 对账（增量必须等于本块长度）
最后：base64 -d /tmp/xxx.b64 | tar xJf - -C /目标目录
      再 md5sum 比对整包
```

> ⚠️ **切块必须 ≤ 900 字符。** 曾经用 1900 字符/块，**长串尾部被静默截断**，两次丢字：
> 目标 15500 字节实到 15495，前 15200 字节 MD5 都不匹配。
> 改成 900 + 每块 `wc -c` 对账后，**7 次传输全部一次成功**。
> **「每块回报 wc -c」这一步不能省** —— 它是唯一能当场发现丢字的手段。

### 3.2 小改动：**走 patch 脚本，别重传整个大文件**

只改几十个字符串时，传一个 3KB 的 Python 脚本（内含 `str.replace` 列表 + 自校验），
让服务器**自己改自己**。本次英文化（13 处替换 / 4 个文件）就是这么做的，一次成功。

patch 脚本必须**自带验证**：
1. 每处替换打印 `[OK]` 或 `[MISS]`
2. 改完做存在性检查（关键字符串在不在）
3. 检查有无中文残留
4. `python3 -m py_compile` 编译验证
5. 改前把原文件 cp 到 `.bak-xxx/` 备份

def read_token() -> str:
    """调试台的口令，从环境变量 DASH_TOKEN 读。空 = 不设防。"""
    return (os.environ.get("DASH_TOKEN") or "").strip()

# Handler 类内、_send 之前
def _token_ok(self) -> bool:
    want = read_token()
    if not want:
        return True
    got = (self.headers.get("X-Dash-Token") or "").strip()
    if not got:
        got = ((parse_qs(urlparse(self.path).query).get("k") or [""])[0]).strip()
    return hmac.compare_digest(got, want)

# do_GET 开头
def do_GET(self) -> None:
    path = urlparse(self.path).path
    if path in PROTECTED and not self._token_ok():

## 七、⚠️ CRLF 陷阱（**本轮撞出来的，最容易再犯**）

### 症状与根因

`kindle/extensions/aistatus/config.sh` 源文件**一直是 CRLF**（253 个 `\r`），
但一直以为没问题，因为：

```bash
grep -c $'\r' config.sh     # 返回 0 —— 骗人的！
```

> **Git Bash 的 `grep` 会做换行符转换，对 CRLF 文件报 0。**

### 后果（如果就这样拷进 Kindle）

`config.sh` 会被 Kindle 的 sh 直接 `source` → `DASHBOARD_URLS="http://...\r"`
→ **下载永远失败，但不报错** → 屏永久停在旧图。属于最难查的一类故障。

### 正确查法

```powershell
$b = [System.IO.File]::ReadAllBytes("config.sh")
$cr = 0; foreach ($x in $b) { if ($x -eq 13) { $cr++ } }
Write-Output "CR=$cr"
```

### 已做的修复

1. 本机源文件剥掉所有 CR（原稿备份为 `config.sh.crlf-bak`）
2. 桌面副本 `C:\Users\peqw0\Desktop\config.sh` 同步修好，与源**逐字节一致**（17162 字节 / CR=0）
3. `.gitattributes` 加显式规则（见上）
4. 记忆里写明「查 CR 必须读原始字节 0x0D」

### 8.3 怎么验「Kindle 真的切到云端了」——**别看 `device_seen`，会骗人**

服务器有两个"设备痕迹"文件，**只有一个可信**：

| 文件 / 字段 | 含义 | 可信度 |
|---|---|---|
| `docs/device_state.json` | 设备 `/report` 上报（带 `ok/hash/src/at`） | ✅ **唯一可信** |
| `/state` 里的 `device_seen` | **任何** `/dashboard.png` 请求都算，**不区分来源** | ❌ 会被浏览器污染 |

**判定标准**：`/report` 带参数来过 → 设备**下载成功且刷屏成功**（`report_state()` 在刷图后才调用）。
`/state` 里 `device.hash` 非空即为真。

**已知的坑（本轮踩到）**：用浏览器打开图片地址时，`?t=<epoch>` 这种缓存击穿参数
**会更新 `device_seen`**，让人误以为"设备刚来过"。**看 `device_seen` 永远判不出真相**
—— 它只说明"有人取过图"。

区分 Kindle 与浏览器：
- **Kindle 的请求不带任何查询参数**（`GET /dashboard.png`）
- **浏览器的请求带 `?t=<epoch>`**；调试台还会去读 `/status?k=…`

## 十二、给下一个 Agent 的提醒

1. **改 `dashboard/` 里任何东西后，必须 `systemctl restart kindle-screen` 才生效**（地址不变），
   Kindle 那边不用动。
2. **不要照 `guide/00` / `guide/02` / `项目现状.md` 操作** —— 那三份是 GitHub Actions 时代的，
   架构已在 2026-09-29 换成"本机 serve.py"、2026-10-01 迁到云端。**以本文件为准。**
3. **改 `config.sh` 之后必须查 CR 字节数为 0**（用 ReadAllBytes 数 0x0D，**不要用 grep**）。
4. **传大文件用 900 字符切块 + 每块 `wc -c` 对账**，别图省事用 1900。
5. **`cat` / `curl` / `tar` 开头会被拦**，换 `python3 -c` 写法。
6. **出图后自检、空图不发（回 404）** 是唯一的安全网 —— 别为了"让它看起来有图"绕过这一步。
7. **`clock.mode: "off"` 的引号不能删**（裸写 `off` 会被 YAML 当布尔 False）。
8. **判"设备来没来"只认 `docs/device_state.json`，不认 `/state` 里的 `device_seen`** ——
   后者对**任何** `/dashboard.png` 请求都计数，你用浏览器点一下就会刷新，
  给出"设备刚来过"的**错误安慰**。区分方法：**Kindle 的请求不带查询参数，
   浏览器的带 `?t=<epoch>`**。真凭据是 `/report` 带 `hash` 参数来过（见 §8.3）。
9. **拷完 `config.sh` 不等于生效** —— 必须重启信息屏让进程重新读变量（见 §8.2）。
   这类"文件换了、进程没换"的静默失效，是本项目最常见的故障形态。
