# 第 2 步 · Kindle 端部署

前提：已经越狱，KUAL 能正常打开（见 [第 1 步](01-越狱与基础环境.md)）。

---

## 1. 拷贝扩展文件

用 USB 连上 Kindle，把项目里的整个 `aistatus` 文件夹拷进去：

```
电脑：Kindle Plan/kindle/extensions/aistatus/     →     Kindle：/mnt/us/extensions/aistatus/
```

拷完的结构应该是这样（用电脑看 Kindle 盘符里的 `extensions` 文件夹）：

```
extensions/
└── aistatus/
    ├── config.sh          ★ 你主要改这个
    ├── config.xml
    ├── menu.json
    ├── clock/             ★ 1440 张时钟小图 + clock.conf（不是拉下来的，是本机生成的）
    │   ├── 0000.png
    │   ├── 0001.png
    │   ├── …
    │   ├── 2359.png
    │   └── clock.conf
    └── bin/
        ├── aistatus.sh
        ├── start.sh
        ├── stop.sh
        ├── refresh.sh
        ├── clock_check.sh
        ├── info.sh
        └── log.sh
```

> **`clock/` 这一份必须一起拷**。它约 4 MB / 1440 个文件，是电脑上用
> `python dashboard/tools/make_clock_assets.py` 生成的 —— 每张对应一天里的一分钟，
> Kindle 按当前时间挑一张贴到屏幕右上角。少了它，那块就是一块空白。
>
> 如果懒得一个个拷，**直接拷整个 `aistatus` 文件夹**最省事。
>
> **改过字号或字体之后**，这份小图要重新生成、重新拷。忘了没忘，
> 在电脑上跑 `python dashboard/tools/layout_check.py`，它会告诉你。

> **如果没有 `extensions` 文件夹**，说明越狱没成功或者 KUAL 没装上，回第 1 步。
>
> **换行符警告**：这些 `.sh` 脚本必须是 Unix 换行（LF）。
> 如果你在 Windows 上打开过并另存，可能会变成 CRLF，Kindle 上会报
> 莫名的 `not found`。用 VS Code / Notepad++ 确认一下，选择「以 LF 结尾」。
> （`clock/` 里那 1440 个 `.png` 是二进制，不受影响。）

## 2. 改配置

用记事本或 VS Code 打开 **`config.sh`**，第一项就是图片地址：

```sh
# 主地址：GitHub 仓库里那张由 Actions 定时生成的图
DASHBOARD_URL="https://raw.githubusercontent.com/<你的用户名>/<仓库名>/main/docs/dashboard.png"
# 备用地址：**故意留空**
DASHBOARD_FALLBACK_URL=""
```

脚本会按顺序试这两个地址，主地址失败才退到备用。**备用留空是故意的**：
备用地址一旦生效，屏幕上的版式可能和仓库里那张不是同一版，
于是"我改了怎么没生效"这种问题根本查不出来（局域网当备胎时真发生过）。
宁可让它失败并在日志里明写「所有地址都失败」。

- 地址哪来：仓库首页点 `docs/dashboard.png` → 那个 raw 链接。**仓库必须公开**
  （Kindle 没法带 token 认证，私有仓库的 Pages 又是付费功能）
- 分支名要对上：URL 里那个 `main` 必须真是你的默认分支，不然 404

注意要是 `.png` 结尾的**具体图片地址**，不是仓库首页。改完保存、弹出 Kindle。

> **证书这条老顾虑可以放下了**：`raw.githubusercontent.com` 实测 TLS 正常、
> 约 1 秒可达。真出问题的话表现是日志里 `certificate error`，
> 那时再考虑别的出口 —— 现在没有"http 的局域网备胎"这条路了。

顺手可以看一下剩下这几组（都有默认值，能跑就别动）：

```sh
# ── 本机时钟（③）───────────────────────────────────────────
CLOCK_MODE=off            # off = 屏幕上不要时间（最省电）。local = Kindle 自己画钟
CLOCK_INTERVAL=60         # 只有 local 才有意义：多久贴一次
CLOCK_WAVE=du             # 贴图波形。du 最快不闪屏；没反应就试 gl16 或 gc16

# ── 整图刷新节奏（②）───────────────────────────────────────
#    取图节奏完全在设备本机算（GitHub 发不了自定义头，云端没法告诉设备几点再来）
FETCH_EVERY_HOURS=1       # 每隔几小时取一次
FETCH_ALIGN_MINUTE=10     # 落在每小时的第几分（Actions 整点起跑，跑完要两三分钟）
QUIET_START=1             # 凌晨 1 点起
QUIET_END=7               # 到 7 点前完全不联网（那几个小时没人看，别白开射频）
FULL_REFRESH_EVERY=1      # 1 = 每次整图都全刷，顺手清掉残影

# ── 省电（⑤）──────────────────────────────────────────────
STOP_FRAMEWORK=1          # 1 = 停掉原生书架界面，最省电（推荐）
USE_RTC_SLEEP=1           # 1 = 用 RTC 闹钟真正休眠
WIFI_SLEEP=0              # 1 = 每次刷新前后关 WiFi（省电但慢）

# ── 网络（⑥）──────────────────────────────────────────────
WIFI_TEST_IP="223.5.5.5"  # ★ 主地址在云端 → 必须填外网地址，不是网关！

# ── 设备校时（⑦）──────────────────────────────────────────
CLOCK_SYNC=1              # 1 = 时间偏了就用服务器 epoch 校准
CLOCK_SYNC_TOLERANCE=120  # 偏差超过多少秒才校
```

> **`CLOCK_MODE=local` 的连锁关系，值得单独说一句**：
>
> 这个开关和电脑上 `dashboard/config.yaml` 里的 `clock.mode` 是**一对**。
> 两边都必须是 `local`，或者都不要用：
>
> | Kindle 端 | config.yaml | 结果 |
> |---|---|---|
> | `local` | `local` | ✅ 正常。图里留白，Kindle 每分钟贴 |
> | `off` | `image` | ✅ 正常。时钟画进图里，跟着整图刷新走 |
> | `local` | `image` | ❌ Kindle 会贴到已画好的时钟上，重叠成一团 |
> | `off` | `local` | ❌ 图里留白，Kindle 又不贴 → 右上角永远空白 |
>
> 改之前先想清楚自己在哪一格。

> **`WIFI_TEST_IP` 该填什么，取决于你的主地址在哪**：
>
> | 主地址 | 填什么 | 为什么 |
> |---|---|---|
> | 云端（https） | 外网地址，如 `223.5.5.5` | 要能上外网才拿得到图 |
> | 本机局域网 | 路由器网关，如 `192.168.31.1` | 只需要局域网通，家里断网也能刷 |
>
> 填错的后果是日志给出**错误的安慰**：填网关却走云端，会告诉您"网络正常"，
> 然后 `[2/6]` 下载失败，让人以为是地址写错了。

## 3. 先测试，再常驻（务必按这个顺序）

**不要一上来就点「启动信息屏」。** 先单独跑一次刷新，把整条链路验通。

### 3.1 先自检时钟（`CLOCK_MODE=local` 时**必做**）

Kindle 上打开 **KUAL → AI 信息屏 → 「🕐 时钟贴图自检」**。

这一步单独拎出来，是因为它验的是一件**没法在电脑上验**的事：
`eips -g 图.png -x 644 -y 18` 这种"贴到指定坐标"的用法，
**官方文档只明确说不支持 K4，对 PW3 没有定论**。必须在你手上这台机器实测。

跑完看屏幕：

| 屏幕上的现象 | 说明 |
|---|---|
| 时钟出现在**右上角** | ✅ 支持 `-x/-y`，一切正常，继续往下 |
| 时钟跑到**左上角** | ❌ 这个固件忽略了 `-x/-y`。把 `CLOCK_MODE` 改成 `off`，同时把电脑上 `config.yaml` 的 `clock.mode` 改回 `image`，时钟就回到"画进图里"的老样子 |
| 时钟**没出现** | 精灵图没拷全或没拷。重新整目录拷一份 `clock/` |
| 时钟**糊成一团** | `CLOCK_WAVE` 换成 `gl16` 再跑一次 |

### 3.2 再跑整链路

Kindle 上打开 **KUAL → AI 信息屏 → 「⟳ 测试下载并刷新一次（排障用）」**。

它会依次检查并打印每一步的结果：

```
[1/6] 检查 WiFi…          → 已连通（耗时 4s，探测目标 223.5.5.5）
[2/6] 下载图片…            → 返回码 0，耗时 2s
[3/6] 校验文件…            → 大小 34120 字节，文件头 89504e47
[4/6] 设备时间对表…        → 偏差 3s，时间够准
[5/6] 写入屏幕…            → 完成（右上角此时是空白的，下一步补上）
[6/6] 本机时钟…            → 贴 0734.png 到 (644, 18)
[设备状态]                 → 电量 / 分辨率 / RTC 节点
```

**成功**：屏幕闪一下全刷，然后出现信息屏画面，**右上角有电量角标**。

**失败**：看 `[N/7]` 停在哪一步，去 [第 4 步 · 排障手册](04-排障手册.md) 对号入座。最常见的几种：

| 现象 | 原因 |
|---|---|
| `[1/7]` WiFi 连不上 | `WIFI_TEST_IP` 填错了。走 GitHub 就得填**外网**地址 |
| `[2/7]` 返回码非 0 | `DASHBOARD_URL` 写错、仓库没 push、或者分支名不对（这三个都是 404） |
| `[2/7]` 返回码 35 / 60 | TLS 握手失败。**设备时间错了会全线 https 失败** —— 见 `[4/7]` |
| `[3/7]` 文件头不是 `89504e47` | 下载到的是 404 页面，不是图片 |
| `[4/7]` 偏差几百秒 | 设备时间不对。`CLOCK_SYNC=1` 会自己校；这个固件改不动时间的话日志会明说 |
| `[6/7]` 显示"未贴" | `CLOCK_MODE=off`，正常 —— 现在就是故意不要时间 |
| `[7/7]` 找不到精灵图 | `battery/` 没拷进 Kindle。右上角留白，无害 |

> **`[4/7]` 这一步为什么会存在**：设备时间错了整个功能就没意义（屏幕上的日期、
> 以及"几点该来拉图"都按它算），而 2015 年的机器放久了真的会漂。
> 以前是靠服务端每个响应带一个 `X-Epoch` 头来对表；**GitHub 发不了自定义头，
> 这条现在没了** —— 剩下的兜底是设备自己走 NTP / 亚马逊的注册流程对时。
> 所以这一步现在只做"检查 + 报偏差"，不再自动校准。

## 4. 启动常驻

测试通过后，KUAL → AI 信息屏 → **「▶ 启动信息屏」**。

首次刷新需要连 WiFi，大概 **10~30 秒**后屏幕会换成信息屏。

之后它就自己运转了 —— **心跳是每分钟一次**：

```
每分钟醒来 ─┬─ 到点了吗？到了就：连 WiFi → 拉整图 → 全刷 → 对表
            │            （图里时钟那块是留白的）
            └─ 不管到没到点，都：从 clock/ 挑出当前这一分钟的小图，
                                 贴到右上角 → 设 RTC 闹钟 → 睡死
  ↑                                                              │
  └──────────────────────── 闹钟响（1 分钟后）───────────────────┘
```

一整天的唤醒次数是 **1440 次**，但绝大多数只是贴一张 386×111 的小图，
**不联网、不重算、不做任何网络请求**。整图只在自己到点的那四次之后才拉。

### 关于省电（`STOP_FRAMEWORK=1` 的含义）

启动时脚本会做两件事：**停掉原生的书架界面**，然后**让设备真正进入休眠**
（不是「屏幕黑了但 CPU 还在跑」，是 `echo mem` 挂起）。

- 墨水屏保持画面本身是**零功耗**的
- 休眠时 CPU 基本不耗电
- 每次唤醒只干几十毫秒的活就继续睡

代价是：**运行期间 KUAL 和书架界面都看不见了**，设备就是一块纯信息屏。

> **续航要说实话**：为了"屏幕上的分钟数永远是对的"，每分钟都要醒一次 ——
> 这是本项目唯一真实的开销。它比"整图模式"（一天醒几十次）费电明显，
> 具体多久充一次电取决于电池状况，别指望"几周"这种数字。
>
> 想省电有两个旋钮，按需要选：
>
> | 做法 | 时间准度 | 省电 |
> |---|---|---|
> | `CLOCK_INTERVAL=60`（默认） | 每分钟都对 | 最费 |
> | `CLOCK_INTERVAL=300` | 以 5 分钟为单位跳 | 省一半以上 |
> | `CLOCK_MODE=off` + 云端 `clock.mode: image` | 跟整图刷新走 | 最省，回到老方案 |
>
> 后两种都不需要重新生成精灵图，改完重启信息屏即可。

这符合「当信息屏用」的需求。但你要知道怎么退出来 —— 见下。

## 5. 想恢复成普通 Kindle 用

三种方式，从优雅到暴力：

### 方式 A：KUAL 停止（前提是你把 `STOP_FRAMEWORK` 设成了 0）

`STOP_FRAMEWORK=0` 时原生界面还在，KUAL → AI 信息屏 → 「■ 停止信息屏」即可。

### 方式 B：放哨兵文件（推荐，`STOP_FRAMEWORK=1` 时的标准做法）

主循环每次醒来都会检查一个文件，发现它就自己退出并恢复系统：

1. USB 连电脑
2. 在 `extensions/aistatus/` 里**新建一个空文件**，文件名就叫 `.stop`
3. 弹出 Kindle，**等一分钟以内**（主循环每分钟醒一次，最近一次醒来就会看到它）

脚本会自动退出、清屏、重新启动原生界面。

> **这是为什么主循环用「检查文件」而不是只靠 kill**：`STOP_FRAMEWORK=1` 时
> 原生界面停了，你没法在设备上操作，也没有 SSH，只能靠 USB 放文件。这条退路必须留着。

### 方式 C：长按电源键强制重启（万能保底）

**长按电源键 40 秒**，Kindle 会强制重启。

重启后系统回到出厂默认状态（原生界面正常），因为脚本**从不修改开机启动配置** ——
它只是在运行时停掉了界面进程，重启自然就恢复了。**这条永远有效，放心折腾。**

## 6. 调参速查

| 你想要 | 改哪里 |
|---|---|
| 屏幕上的时间更省电（牺牲分钟精度） | `CLOCK_INTERVAL=300`（每 5 分钟贴一次） |
| 完全不贴本机时钟 | `CLOCK_MODE=off`（**现在就是这个，最省电**），并且电脑上 `config.yaml` 的 `clock.mode` 也要是 `"off"`。两边不一致的话：那边 `image` → 图上画一个几小时前的假时间；那边 `local` → 右上角永远一块空白 |
| 时钟显示糊 / 贴不上去 | `CLOCK_WAVE=gl16`（老固件对 `du` 支持不一） |
| 想让图更及时 | 设备上改 `FETCH_EVERY_HOURS=1`（已经是 1）；**真正卡着的是云端** —— Actions 的 cron 在 `.github/workflows/build.yml`，两边要一起动 |
| 画面残影明显 | `FULL_REFRESH_EVERY=1`（每次整图都全刷，默认就是 1） |
| 更省电 | 先确认它**真的睡进去了**（日志里"计划 600s，实际睡了 XXXs"）；睡不进去比什么都费电。其次 `QUIET_START`/`QUIET_END` 把没人看的时段整段关掉，再其次 `STOP_CHECK_MAX_SLEEP` 调大 |
| 设备时间总是不对 | 保持 `CLOCK_SYNC=1`；实在校不上见 [排障手册](04-排障手册.md) 的"时间不准"一节 |
| 想保留书架界面 | `STOP_FRAMEWORK=0`（耗电明显变快） |
| 屏幕角落显示状态文字 | `SHOW_STATUS_LINE=1`，再调 `STATUS_ROW`（按字符行算，自己试） |
| 电量低时不闪烁打扰 | `LOW_BATTERY_THRESHOLD=10` |
| 不想用云端 | 把 `DASHBOARD_URL` 和 `DASHBOARD_FALLBACK_URL` 的值**对调**，`WIFI_TEST_IP` 改回网关 |

改完 `config.sh` 后需要**重启信息屏**：放 `.stop` 等它退出，再点「启动」。

## 7. 日志

KUAL → AI 信息屏 → 「☰ 查看日志」，或者直接看
`/mnt/us/extensions/aistatus/aistatus.log`（USB 连电脑也能看，就是普通文本）。

日志会自动裁剪到最近 500 行，不会撑爆存储。里面能看到每次刷新的时间、
WiFi 等待耗时、下载结果、休眠时长，排障主要靠它。

启动时前几行会先把关键状态交代清楚，**先看这几行**：

```
=== 启动 AI 信息屏 ===
URL: https://…
备用: http://192.168.31.158:8000/dashboard.png
整图：优先听云端时刻表（X-Next-Image），拿不到才按 白天 3600s / 夜间 10800s 轮询
时钟：本机贴图，每 60s 一次，坐标 (644,18)
```

注意最后一行 —— 如果它写的是「时钟：本机贴图**未就绪**」，
说明 `clock/` 没拷全，右上角会一直是空白的，别去别处找原因。
时钟相关的告警**每个问题只报一次**（不然每分钟一条会把日志刷爆），
所以看到一条之后就别等第二条了，直接处理。
