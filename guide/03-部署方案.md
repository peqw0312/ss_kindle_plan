## 2. 配一个更准的天气源（可选，但推荐）

不配也能跑 —— 会自动退回 Open-Meteo。但 Open-Meteo 是全球数值模式
（约 11km 网格）插值到你那个坐标，**在国内离实况有距离**：跟中国气象局的实时观测比，
温度能差 1~2°C、湿度差 8 个点、风速差一倍，而且**没有灾害预警**。

和风天气在国内是融合实况 + 官方合作数据，带空气质量和预警，免费额度
（每月 5 万次）对这个项目来说是天文数字（一天 4 次，一个月约 130 次）。

**开通步骤**（免费，只要手机号或邮箱，不绑卡、不实名）：

1. 打开 <https://dev.qweather.com> 注册，选「免费订阅」
2. 控制台 → 项目管理 → 创建项目，类型选 **Web API**
3. 在控制台里抄下两个东西，填进 `dashboard/config.yaml`：

```yaml
weather:
  provider: qweather
  qweather:
    api_host: "abcdefg.re.qweatherapi.com"   # ← API Host
    api_key: "你的32位Key"                    # ← API Key
```

> ### ⚠️ 这里有个必踩的坑：旧域名已经停服
> 网上能搜到的教程几乎都写着 `devapi.qweather.com` 或 `api.qweather.com`，
> **照抄一定失败**：
>
> - `devapi.qweather.com` —— **2026-01-01 停止服务**
> - `api.qweather.com` —— **2026-06-01 停止服务**
>
> 必须用控制台发给你那个**专属 API Host**（形如 `xxxxxx.re.qweatherapi.com`）。
> 这个改动是和风自己推的，跟本项目无关。

不想把 Key 写进配置文件的话，用环境变量：

```bash
# Windows
set QWEATHER_KEY=你的Key
# macOS / Linux
export QWEATHER_KEY=你的Key
```

> **云端方案注意**：走云端时（方案 A）Key 是**放在 `dashboard/config.yaml` 里上传的**，
> 云端跑的时候没有你本机的环境变量。所以走云端就把 Key 写进配置文件。

配好之后跑一次，日志里应该出现 `天气：和风天气`。如果还是 `Open-Meteo`，
说明 Host 或 Key 没生效 —— 看第 6 节。

**坐标怎么填**：`location.latitude` / `longitude`，去高德或百度地图上右键
「复制坐标」，小数点后 4 位足够。默认值是杭州临平山。

## 3. 方案 A · 云端出图（推荐）

### 它是怎么工作的

`dashboard/app.py` 不是"发一张静态图"，而是**自己就是生成器**：

```
Kindle 来拉 /dashboard.png
    ├─ 缓存还没过期（按时刻表判）→ 直接把上一张发出去，0 秒
    └─ 过了最近一个时刻点 → 抓天气 / 行情 → 排版 → 存进内存 → 发出去（约 2 秒）
```

**"过期"是按时刻表的**，不是"上一张图过了多少分钟"。时刻表在
`config.yaml` 的 `cloud.refresh_at`：

```yaml
cloud:
  refresh_at: ["00:05", "05:10", "12:00", "15:05"]
```

判定用 `location.timezone`（Asia/Shanghai），**不是服务器本地时间** ——
云端容器多半跑在 UTC，照本地时间判会让 `00:05` 落到北京时间 `08:05`，
于是每天上午屏幕上是昨天的日期。这一点在代码里专门处理了，自检也覆盖。

为什么是这四个点：

| 时刻 | 为什么 |
|---|---|
| `00:05` | **翻日期**。不然每天 00:00–12:00 屏幕上还是昨天的大字日期和农历，日历条是这块屏的主体，错半天很扎眼。顺带抓一次美股盘中 |
| `05:10` | **美股收盘**。夏令时 04:00 收、冬令时 05:00 收，取两者之**后**，一年到头不用改 |
| `12:00` | 你要的时间点。此时美股当日已收官，拿到的是最终值 |
| `15:05` | **A 股收盘**（沪深 15:00 收）。不然上证会整天停在 11:30 午休前的价 |

所以云端**不落盘**，`output:` 那几项配置在云端是无关项。它复用的还是
`generate.py` 的抓取管线（`collect()`），不是另抄一份 —— 本地调好的板式
直接就等于云端的样子。

> **需要更频繁的话**：往 `refresh_at` 里加时刻就行。留空则退回
> `refresh_minutes`（默认 15 分钟）的固定间隔，行为跟老版本一样。
> 改完记得**重新发布**线上。

### 三个接口

| 路径 | 给谁用 | 说明 |
|---|---|---|
| `/dashboard.png` | **Kindle** | 图片本体。带 `X-Epoch` 响应头，Kindle 拿它校准系统时间。`?force=1` 可以强制立刻重算一张 |
| `/` | 你自己 | 网页预览版，手机电脑打开就能看当前这张图 |
| `/health` | 排障 | JSON 状态：生成时间、时刻表、下次出图时间、时钟模式与坐标、字体、错误原因 |

### 发布 / 更新线上

**改了 `dashboard/` 里的东西要重新发布**，线上才会变。发布完链接不变。

> 没改代码、只是数据在变 → 不用管。云端按时刻表自己重算。

### 怎么知道云端是好的

浏览器打开：

```
https://<你的>.app.workbuddy.host/health
```

```json
{
  "ok": true,
  "generated_at": "2026-09-18T12:00:08",
  "fonts": "常规=Noto Sans SC Regular / 粗体=Noto Sans SC Bold",
  "weather_source": "Open-Meteo",
  "weather": "晴间多云 28°",
  "quotes_valid": 3,
  "age_seconds": 184.2,
  "schedule": "00:05、05:10、12:00、15:05（Asia/Shanghai）",
  "next_build_at": "2026-09-18T15:05+08:00",
  "clock_mode": "local",
  "clock_region": [644, 18, 1030, 129],
  "notes": [],
  "builds": 3
}
```

看这几个字段就够了：

- `ok: false` → 出图失败，`reason` 里写着原因。**服务不会因此挂掉**，
  它会继续发上一张好图（`age_seconds` 会越来越大），你还有时间慢慢修。
- `age_seconds` **大于"距上一个时刻点的时间"** 才说明有问题。正常情况它会一直涨，
  涨到下一个时刻点就归零 —— 这是设计如此，不是卡住。真正的判据是 `next_build_at`：
  它应该是个未来的时间点。
- `clock_mode` 应该是 `local`，`clock_region` 应该和 Kindle 上
  `clock/clock.conf` 里的坐标一致。**线上通常会比本机大 1px**（本机
  `[644, 18, 1030, 129]`、线上 `[645, 18, 1030, 129]`），因为两边的 Noto
  一个是独立 `.otf`、一个是 `.ttc`，字形度量差 1px ——
  实测是白压白、屏幕上看不出来，属正常。`check_cloud.py` 会把差值打出来，
  `≤2px` 判一致。
  **差得更多就要处理**，否则时钟会贴偏，而屏幕上只会表现为"时钟位置有点怪"。
- `fonts` 必须含 `SC` 或 `CJK`。如果写着 `DejaVu` 之类，中文会变成方块 □□□。
- `quotes_valid` / `quotes_total` → 行情抓到了几条。

### 要花钱吗 / 要绑卡吗

不用。不需要注册账号、不需要实名、不需要绑卡。

### ⚠️ 隐私：链接是公开的

**任何拿到这个链接的人都能看到你的屏幕内容** —— 包括日历条上的城市名和你的自选行情
（`/health` 还会显示出图状态）。它不会被搜索引擎收录，但别随手往群里发。

介意的话就走方案 B：图只在自家局域网里跑，出门就没了。

### 不想用了

在 **设置—数据管理—应用** 里可以管理 / 下线已发布的应用。下线之后链接立刻失效，
Kindle 会自动退到备用地址（方案 B）。

## 4. 方案 B · 本机局域网（备用）

### 起服务

```bash
python dashboard/serve.py
```

启动时会直接把该填的地址算出来打给你：

```
 图片   dashboard.png  61 KB，生成于 09-18 16:52（0 分钟前）
--------------------------------------------------------------
 Kindle 端填： http://192.168.31.158:8000/dashboard.png
--------------------------------------------------------------
```

**把那一行地址抄下来**，填进 Kindle 的 `DASHBOARD_FALLBACK_URL`。

### 为什么不用 `python -m http.server`

这是一个**踩过坑的替代**，不是重复造轮子：

`python -m http.server` 带 `Last-Modified` 且认 `If-Modified-Since`。
Kindle 上的 curl/wget 一旦收到 **304 就不写文件**，于是屏幕永远停在上一张，
而两边日志都显示"成功"——这是最难查的那种故障。`serve.py` 把协商头整个摘掉，
再压上 `no-store`，每次都是完整的 200 + 图片本体。

云端那版 `app.py` 同样守这条规矩（有专门的自检项验证）。

### 让电脑按时出图

`install_task.py` 会**读 `config.yaml` 里的 `cloud.refresh_at`**，在你指定的那几个
时刻各注册一个触发器 —— 不是"每 60 分钟一次"那种固定间隔。

```bash
python dashboard/tools/install_task.py           # 按 refresh_at 注册（默认 00:05 / 05:10 / 12:00 / 15:05）

python dashboard/tools/install_task.py --run     # 立刻跑一次验证
python dashboard/tools/install_task.py --status  # 看上次运行结果和返回码
python dashboard/tools/install_task.py --remove  # 不想要了就注销
```

`--status` 里 **返回码 0 = 成功**。

想临时改成别的时刻（不改配置文件）：

```bash
python dashboard/tools/install_task.py --at 07:30,12:00,18:30    # 逗号分隔
```

留空的 `refresh_at` 会退回固定间隔，用 `--minutes` 指定：

```bash
python dashboard/tools/install_task.py --minutes 60    # 就是老版本的每小时一次
```

> **改完 `config.yaml` 的 `refresh_at` 要重跑一次 `install_task.py`**，
> 计划任务才会跟着变 —— 它只在注册那一刻读配置。

macOS / Linux 用 cron（注意：`refresh_at` 那种"每天固定几个点"用 cron 写更自然）：

```cron
5 0,5,12,15 * * * cd /你的/项目路径 && /你的/项目路径/.venv/bin/python dashboard/generate.py -c dashboard/config.yaml >> /tmp/aistatus.log 2>&1
```

上面这行 = 每天 00:05 / 05:10 / 12:00 / 15:05 各跑一次。
想更简单也可以干脆每 10 分钟跑一次，代价是上游调用次数上去了：

```cron
*/10 * * * * cd /你的/项目路径 && /你的/项目路径/.venv/bin/python dashboard/generate.py -c dashboard/config.yaml >> /tmp/aistatus.log 2>&1
```

### serve.py 那个窗口要一直开着

它是前台进程，关掉窗口服务就停了。做成开机自启：
`Win+R` → `shell:startup` → 在打开的文件夹里放个快捷方式，目标填
`"<项目的python路径>" "<项目>\dashboard\serve.py"`，「起始位置」填项目根目录。

### ⚠️ 关掉睡眠

**电脑睡着了，图就不会更新**，而 Kindle 那边**不会报错**，只是继续显示旧图。

Windows：设置 → 系统 → 电源 → 「睡眠」改成 **从不**。
macOS：系统设置 → 锁定屏幕 → 「显示器关闭后允许进入睡眠」改成 **永不**。

> 显示器可以照常关，不影响。走方案 A 的话这条不用管。
>
> **电脑的 IP 最好固定**：路由器一般会把同一地址续给同一台设备，但重启后偶尔会变。
> 稳妥做法是在路由器里做一条 **DHCP 静态绑定**（把电脑 MAC 绑到 192.168.31.158）。

## 5. 把 Kindle 指向哪里

编辑 `kindle/extensions/aistatus/config.sh`：

```sh
# 主地址：云端（电脑关机也能出图）
DASHBOARD_URL="https://<你的>.app.workbuddy.host/dashboard.png"
# 备用地址：本机局域网（电脑开着才有）；留空也行
DASHBOARD_FALLBACK_URL="http://192.168.31.158:8000/dashboard.png"

UPDATE_INTERVAL=3600        # 兜底值，正常用不上：云端会直接告诉设备下次几点来取
WIFI_TEST_IP="223.5.5.5"    # 主地址在云端 → 必须填外网地址
```

三个值的道理：

- **`UPDATE_INTERVAL` 现在只是兜底**：云端每个响应都带一个 `X-Next-Image` 头，
  告诉 Kindle 下一个换图时刻是几点，设备照着睡到那儿就行 —— 一天连四五次 WiFi，
  而不是每小时去问一次（问 24 次有 20 次拿回来的是完全相同的图）。
  只有走局域网备用地址（`serve.py` 静态发文件、不参与调度）才会用到这个值。
  **想改"几点换新图"，改的是 `cloud.refresh_at`，重新发布就完了，这边不用动。**
- **`WIFI_TEST_IP` 填外网地址**：主地址在云端，填网关（192.168.x.1）只能证明
  局域网通，会让日志给出错误的安慰。用 IP 不用域名，省一次 DNS。
  **如果你只用备用地址**，就该改回网关 —— 那时 Kindle 只需要局域网通。
- **留着备用地址**：主地址是 https，而 2015 年前后的 Kindle 根证书库偏旧。
  万一它不认这张证书，`curl` 会直接报 certificate error，这时脚本会自动退回
  http 的局域网地址，不至于当场瘫掉。

> **别忘了 `clock/`**：Kindle 端的时钟靠本地那 1440 张精灵图。
> 拷 `aistatus` 目录时**整个目录一起拷**，别只挑 `.sh`。
> 换过字号或字体之后要重跑 `make_clock_assets.py` 并重拷。

然后按 [guide/02](02-Kindle端部署.md) 拷进 Kindle、在 KUAL 里启动。

## 6. 常用调试命令

```bash
# 只测板式，完全不联网（最快，用来调字号和布局）
python dashboard/generate.py --offline

# 把时间固定住，方便对比两次渲染的差异
python dashboard/generate.py --now 2026-09-18T08:30

# 数据源自检：某个源挂了的时候用它定位
python dashboard/tools/probe_sources.py
python dashboard/tools/probe_sources.py --only quotes     # 只看行情
python dashboard/tools/probe_sources.py --only weather    # 只看天气（含各源对比）
python dashboard/tools/probe_sources.py --only calendar   # 只看日历（不需要联网）

# 版式自检：改字号 / 内边距之前先跑，量出每块占多少像素，
# 并且顺带检查「时钟精灵图和版面几何是不是同一套」
python dashboard/tools/layout_check.py

# 生成时钟精灵图（1440 张，约半分钟）。改过字号 / 时钟样式 / 字体之后必须重跑，
# 然后把整个 kindle/extensions/aistatus/clock/ 重拷进 Kindle
python dashboard/tools/make_clock_assets.py
python dashboard/tools/make_clock_assets.py --force     # 指纹没变也强制重生成

# 云端服务自检：本机起进程试跑（验接口、验图片规格、验 304、验时刻表判定）
python dashboard/tools/check_cloud.py
# 验线上（改完代码重新发布之后跑这个）
python dashboard/tools/check_cloud.py --url https://<你的>.app.workbuddy.host

# 农历对拍：拿 lunar_python 验农历表和节气（需要 pip install lunar_python）
python dashboard/tools/verify_lunar.py
```

`layout_check.py` 会在 `.workbuddy/_preview/` 下出几张预览图（平时 / 节日 / 节气 /
春节 / 预警各一张），改完板式直接看那几张最快。

真机上时钟就贴偏了，在电脑上看预览图完全正常。

## 7. 定制化

改动都在 `dashboard/config.yaml` 一个文件里。走方案 B 的话**改完不用重启任何东西**，
下一轮定时任务自动生效；走方案 A 的话**要重新发布一次**线上。

### 换城市

```yaml
location:
  name: 深圳
  latitude: 22.5431
  longitude: 114.0579
```

`name` 只是显示用的文字（出现在日历条右侧）。

### 换自选股

```yaml
quotes:
  items:
    - { code: usNDX,     name: 纳指100 }
    - { code: sh000001,  name: 上证指数 }      # 代码可以只写数字：000001
    - { code: sh600519,  name: 贵州茅台 }
    - { code: hk00700,   name: 腾讯控股 }
```

| 前缀 | 市场 | 例子 |
|---|---|---|
| `sh` | 上海 | `sh600519` |
| `sz` | 深圳 | `sz399006` |
| `bj` | 北京 | `bj430047` |
| `hk` | 中国香港 | `hk00700` |
| `us` | 美国 | `usAAPL`、`usNDX`（纳指100）、`usINX`（标普500）|
| `bitget:` | 加密永续合约 | `bitget:BTCUSDT`（默认注释掉了） |

> **行情是三列并排的**，超过 3 条就会换行。加之前先跑 `layout_check.py`
> 看还放不放得下。

### 时钟

时钟有**两个**地方要配，而且必须成对：

```yaml
# dashboard/config.yaml
clock:
  style: cn12     # cn12 = 「下午 4:34」（默认，老人最直白）
                  # en12 = 「4:34 PM」
                  # h24  = 「16:34」
  mode: local     # local = 图里留白，Kindle 自己贴（推荐）
                  # image = 画进图里，跟着整图刷新走
  font: 'C:\Windows\Fonts\Noto Sans SC (TrueType).otf'
  font_bold: 'C:\Windows\Fonts\Noto Sans SC Bold (TrueType).otf'
```

```sh
# kindle/extensions/aistatus/config.sh
CLOCK_MODE=local        # 必须和上面的 mode 一致
CLOCK_INTERVAL=60       # 多久贴一次
```

**`font` / `font_bold` 这两项别删。** 它们决定出图和生成精灵图时用哪套字：

- 云端解析到的是 **Noto Sans CJK SC**，本机默认解析到 **微软雅黑**
- 两者字形不同，最要命的是**行高差 10px**
- 而时钟区的坐标正是用这些字量出来的 —— 精灵图按 Noto 的尺寸生成、
  却贴到雅黑量出来的留白上，真机上就是"看着像另一块拼上去的"

所以把这两个路径指到本机的 Noto，本机、云端、精灵图三边就都对上了。
**路径写错生成脚本会直接报错停下**，不会默默用别的字体糊过去。

> **页脚那行「更新 HH:MM」是图的生成时刻**，不是当前时间。
> `mode: local` 之后这不是缺陷 —— 一眼就能看出"这是 12:00 那一版的数据"。

### 云端出图时刻表

```yaml
cloud:
  refresh_at: ["00:05", "05:10", "12:00", "15:05"]   # 按 location.timezone 判定
  refresh_minutes: 15     # refresh_at 留空时的兜底间隔（分钟）
```

改这个等于改"图有多新"，动机见本文第 3 节的那张表。
加时刻就加调用次数，减时刻屏幕上就会旧得更久 —— 自己权衡。

这个值现在**同时决定了两件事**，因为云端会把算好的下一个时刻通过 `X-Next-Image`
头发给设备：它既是"图什么时候变新"，也是"Kindle 多久去看一眼"。
改完重新发布，Kindle 那边自动跟上，不用改 `config.sh`、不用重拷文件。
（只有走局域网备用地址时才退回 `UPDATE_INTERVAL` 的固定轮询。）

### 关掉某个区块

```yaml
weather:
  enabled: false     # 关掉天气卡片
quotes:
  enabled: false     # 关掉行情
calendar:
  enabled: false     # 关掉整个日历条
```

关掉之后省下来的高度会**自动均摊**成其他区块的内边距，不会留下一块空白。

### 今日速览（默认关闭）

`digest.enabled` 默认是 `false` —— 屏幕只剩 日历 + 天气 + 行情，一眼看完。
它需要额外一个模型接口，而且原方案用的是 GitHub Models（需要 GitHub token）。
既然已经不走 GitHub 了，用之前先确认这条路在你这台机器上通，
或者把 `endpoint` / `model` 一起换成国内可直连的接口。

填不上也不会崩，会自动降级成「直接显示新闻标题」。

## 8. 出问题了怎么查

### 云端图不更新

1. 打开 `https://<你的>.app.workbuddy.host/health` 看 `ok` 和 `reason`
2. `next_build_at` 是个**过去**的时间 → 后台刷新线程卡了，重新发布一次
3. `age_seconds` 涨得比"距上一个时刻点的间隔"还多 → 云端抓数据失败，
   `reason` 里有具体报错
4. `ok: true` 但 `generated_at` 停在某个时刻点很久不动 → 同上，看 `notes`
5. `fonts` 里没有 `SC`/`CJK` → 云端字体没找到，中文会变方块

> **`age_seconds` 一直涨是正常的** —— 它涨到下一个时刻点才归零。
> 别拿它跟老版本的 `refresh_seconds` 比，那个字段已经不在了。

### 时钟位置不对 / 右上角空白

这是本方案唯一"电脑上看着正常、真机上不对"的故障，按顺序查：

| 现象 | 先查 | 多半是 |
|---|---|---|
| 右上角**一直空白** | Kindle 启动日志里「时钟：本机贴图**未就绪**」那一行 | `clock/` 没拷全。整个目录重拷一次 |
| 时钟在**左上角** | 跑 KUAL「🕐 时钟贴图自检」 | 这个固件不支持 `eips -x/-y`，改 `CLOCK_MODE=off` 并回退 `clock.mode: image` |
| 时钟**偏几像素**、像拼上去的 | 比对两边：`/health` 的 `clock_region` vs Kindle 上 `clock/clock.conf` 的 `CLOCK_X/Y/W/H` | 字号或字体改过而精灵图没重生成。跑 `make_clock_assets.py` 重生成重拷 |
| 时钟**和图上其他字不同款** | `layout_check.py` 最后的指纹那一行 | `config.yaml` 的 `clock.font` 没指到 Noto，或指的路径不存在 |
| 时间**整体错几小时** | `refresh.sh` 的 `[4/6]` 那步 | 设备时区/时间不对。`CLOCK_SYNC=1` 会自己修；修不了看[排障手册](04-排障手册.md) |

不确定自己在哪一格，就回 [第 2 步的配置对照表](02-Kindle端部署.md) 看
`CLOCK_MODE` 和 `clock.mode` 那四种组合。

### 天气还是 Open-Meteo

日志里搜这几行：

| 日志 | 含义 | 怎么办 |
|---|---|---|
| `没配和风天气的 API Host / Key` | 配置里是空的 | 看第 2 节，填 `api_host` 和 `api_key` |
| `和风天气返回 code=401` | Key 不对 | 重新复制一次，注意别带上多余空格 |
| `和风天气返回 code=403` | Host 不对 | **八成用了停服的旧域名**，换成控制台给的专属 Host |
| `天气请求失败` | 网络不通 | 是不是 `network.use_env_proxy` 开错了 |

不管哪种，**屏幕都不会空着** —— 会自动退回 Open-Meteo，页脚会如实写出
这一轮用的是哪个源。

### 本机图不更新

1. `python dashboard/tools/install_task.py --status` —— 返回码是不是 0
2. `docs/dashboard.png` 的修改时间是不是最近的
3. 电脑睡了没有（第 4 节）
4. `serve.py` 打出来的「生成于 X 分钟前」是几分钟

### Kindle 上是旧图

在 KUAL 里点「⟳ 测试下载并刷新一次」，或者 SSH 跑：

```bash
/mnt/us/extensions/aistatus/bin/refresh.sh
```

它会把主地址和备用地址**都试一遍**，每个打印返回码和耗时，然后按返回码告诉你
问题在哪 —— 证书、DNS、还是服务端 4xx/5xx。

更多见 [guide/04-排障手册.md](04-排障手册.md)。
