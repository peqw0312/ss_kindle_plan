三、一张图是怎么上屏的

A · 平时（你什么都不按）

  1. serve.py 起来就先出一张，之后每 10 分钟一轮。
  2. 抓和风 + 新浪 → 画 docs/dashboard.png。
  3. 出完自检：这张有没有天气那一块？没有就不发。
  4. 屏每分钟来取一次；取回来和屏上那张校验和一样就不重绘（所以不闪）。
  5. 屏上"更新 HH:MM"就是第 3 步那张的出图时刻，最多比现在旧 10 分钟。

B · 你在调试台按「立刻出图」

  1. 页面 POST /publish?skin=…（同源，不用 token）。
  2. 本机跑同一段 generate.py，实测 1.1 秒。
  3. 自检通过 → 记下这张的校验和；选过版式就写进 docs/skin.txt，以后每轮都按它出。
  4. 顺手刷一次皮肤墙（docs/skins/），并进入调屏模式：接下来 30 分钟屏来得更勤。
  5. 屏下一班来取（实测约 65 秒一班；更新过屏里的脚本之后能到 10 秒）。
  6. 屏上报"我贴的是 337037550 60233"→ 真值卡显示「和本机这张是同一张 ✓」。

四、五条不能破的规矩每一条都是踩过坑换来的

1 · 零成本不付费、不绑卡、不注册。和风要实名是你自己接受的例外。
2 · 凭据绝不进仓库仓库是公开的。Key 只在本机那个被 .gitignore 挡着的 env 文件里；调试台只报"哪个在、哪个不在"，值永远不经过页面。
3 · 空图不出门画出一张空白图是不会报错的。所以发图这一端必须自己查。真出过事故：一张没带凭据的测试图盖在屏上几小时。
4 · 电脑不在 = 屏停在最后一张，不会自愈这是去掉云端之后新添的一条，也是这次决定的全部代价。Windows 自动更新重启、服务被停、路由器抽风都算。所以：路由器给 192.168.31.158 做 DHCP 保留，是现在最该做而还没做的一件事。
5 · 界面不许说机器没做的事本项目反复栽在这上面：调试台喊"每 30 秒一班"而屏实际 66 秒、页脚写死"行情 腾讯"而数据早换成新浪、"距今 4 小时"其实是 46 小时。现在凡是节奏、来源、时间，一律量出来给。

五、插线会发生什么最容易把人绕晕的一节

  • 插线 = 屏变成一块 U 盘（电脑上看到 D:）。这时候屏幕点不动，任何"点一下屏"都要先拔线。
  • 正在被 ash 执行的脚本不能原地覆盖（屏是 FAT，没有 inode 那层间接）。所以顺序只能是：屏上点「停止信息屏」→ 插线 → 拷 → 拔线 → 点「启动信息屏」。
  • 仓库工作副本是 CRLF，屏上必须是 LF。直接拷会把 \r 带进 shell 变量，症状是"配置看着对、行为完全不对"。拷之前必须转换。
  • config.sh 只在启动时读一次。拷完不重启脚本 = 白拷。
  • 屏睡着时什么都进不去：射频是关的，ping 不通、也叫不醒。以前为了省电让它睡，2026-09-29 起长期插电源，改成不睡了。

六、出问题时按这个顺序查别从屏开始猜

症状先看这里
屏上信息旧 / 缺一块 调试台屏上现在这张那一行 —— 它会说"本机发的是…：为什么不发"。再看本机凭据那栏和完整构建日志（现在是本机上一轮出图的真实输出）。
屏整个停在一张不动 看 .workbuddy/_serve.log 有没有每分钟一条 curl/7.86.0 的取图请求，或调试台那句"上一班隔 N 秒来一班"。一条都没有 = 屏没醒 / WiFi 掉了 / 这台没在跑，跟图的内容无关。
按了按钮没反应 GET :8731/state 看 can_build / served / note。按钮一律回话；不回话就是请求没到本机（多半是页面被当成文件双击打开了）。
换皮肤没生效 GET /skin.txt 就是屏该用的那套；空 = 按 config.yaml 的默认。选过之后每轮自动出图都会照它出。
电脑重启之后屏没回来 serve.py 不是开机自启的（脚本从不改系统的开机配置）。要么手动跑一次 python dashboard/serve.py，要么先接受"屏停在最后一张"。
